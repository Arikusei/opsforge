# OpsForge

Пет-проект контура автоматизации B2B-продаж смазочных материалов. Учебный контур: не чат-демо, а путь от заявки до устойчивого процесса с агентом, RAG и вебхуками.

## Что умеет

- Квалифицировать заявку с сайта и завести сделку в CRM (live или mock).
- Обработать пропущенный звонок PhonePBX: лид, задача на перезвон, сообщение в TeamChat.
- Отвечать сотрудникам из корпоративной базы знаний (RAG: BM25 + векторы).
- ReAct-агент с инструментами: каталог, лид, черновик КП, уведомление продаж, регламенты.
- Вызывать инструменты **нативно** — через OpenAI tools API и Anthropic `tool_use`, с деградацией в JSON-протокол и demo-контур.
- Считать по каждому прогону токены, стоимость и латентность, писать трейсы шагов и отдавать метрики в Prometheus.
- Отдавать те же сценарии в n8n, через webhook API и через MCP для Claude/Cursor.
- Подниматься в Docker с Nginx, MinIO/S3 и Prometheus-метриками.

Демо **работает без ключей LLM и CRM**. Если задать OpenAI или Anthropic — агент переключается на живую модель.

## Агентный контур

Цикл живёт в `apps/api/app/agents/react.py`. Схемы инструментов описаны один раз
в `agents/tools.py` (JSON Schema) и транслируются в формат нужного провайдера
в `agents/schemas.py`, поэтому OpenAI и Anthropic получают одинаковый контракт.

Три режима работы, переключение автоматическое:

| Режим | Когда | Что делает |
| --- | --- | --- |
| `native_tools` | есть ключ, `AGENT_NATIVE_TOOLS=true` | tool calling средствами API, до `AGENT_MAX_ITERATIONS` шагов |
| `json_protocol` | модель не приняла `tools` | агент просит модель вернуть `{"tool": ..., "args": ...}` |
| `demo` | ключей нет или API упал | детерминированные правила по ключевым словам |

Устойчивость к ошибкам модели:

- аргументы инструментов проверяются по схеме (обязательные поля, типы, enum) —
  пустое `company` не создаёт лид «Не указана», а возвращается модели как ошибка;
- битый JSON в аргументах и неизвестное имя инструмента тоже приходят обратно
  как наблюдение, поэтому модель может исправиться на следующем шаге;
- при исчерпании лимита итераций агент делает финальный запрос уже без
  инструментов, чтобы вернуть ответ по собранным данным, а не пустоту;
- наблюдения урезаются перед отправкой обратно в модель — экономия токенов.

## Наблюдаемость LLM

Каждый прогон пишется в `agent_runs`, каждый запрос к модели — в `llm_calls`:
режим, число итераций, вызванные инструменты, токены, расчётная стоимость,
латентность, текст ошибки.

```
GET /api/chat/status          # провайдер, модель, режим, список инструментов
GET /api/agent/runs           # сводка прогонов: токены, стоимость, фолбэки
GET /api/agent/runs/{run_id}  # шаги, наблюдения инструментов, разбивка по вызовам
GET /metrics                  # Prometheus
```

Метрики Prometheus: `opsforge_llm_calls_total`, `opsforge_llm_tokens_total`,
`opsforge_llm_cost_usd_total`, `opsforge_llm_latency_seconds`,
`opsforge_agent_runs_total`, `opsforge_agent_iterations`,
`opsforge_agent_tool_calls_total`.

Стоимость считается по таблице прайсов в `app/observability/tracing.py`;
неизвестная модель даёт 0, а не выдуманную цифру. Через `TRACE_WEBHOOK_URL`
трейс дублируется наружу — например, в n8n для алертов по стоимости и падениям
инструментов.

## Eval

Золотой набор из 28 кейсов: подбор продукта, создание лида, недостающая
квалификация, КП, регламенты, гардрейлы (цена, срок доставки, несуществующий
допуск), эскалация, многошаговый сценарий, вопрос не по теме.

```powershell
cd apps\api
.\.venv\Scripts\python.exe eval\run_eval.py --provider demo
.\.venv\Scripts\python.exe eval\run_eval.py --provider openai
.\.venv\Scripts\python.exe eval\run_eval.py --provider openai --no-native-tools
```

Считаются: pass rate, доля правильного выбора инструментов, отсутствие лишних
вызовов, покрытие содержания ответа, нарушения гардрейлов, цитируемость,
латентность p50/p95, суммарные токены и стоимость. Отчёты (JSON + markdown)
складываются в `eval/reports/`, прогон идёт в отдельную БД и не засоряет лиды.

Baseline demo-контура — `eval/reports/demo-demo.md`: **pass rate 50%**, при нуле
нарушений гардрейлов сыпятся регламенты, эскалация и многошаговые сценарии.
Это точка отсчёта, с которой сравнивается живая модель.

## Личный вклад (для портфолио)

Собрал учебный AI Ops вокруг типичных процессов B2B-дистрибьютора смазочных материалов: квалификация заявки, пропущенный звонок, подбор NSF/СОЖ/покрытий. Вынес оркестрацию в n8n, а доменную логику и RAG — в тестируемый API. Сделал контур, который можно показать без ключей и затем включить live-интеграции через `.env`.

Агентную часть довёл с «парсинга JSON из текста ответа» до нативного tool calling
двух провайдеров: единые JSON-схемы инструментов, валидация аргументов с
возвратом ошибки в модель для самокоррекции, лимит итераций с добивающим
запросом, три уровня деградации (native → JSON-протокол → правила). Поверх
поставил наблюдаемость — токены, стоимость и латентность по каждому вызову в
БД и Prometheus — и eval-набор из 28 кейсов с метриками выбора инструментов,
гардрейлов и цитируемости, чтобы изменения промпта проверялись числами.
Проводной формат обоих SDK и все ветки деградации закрыты тестами (40 шт.,
без обращений к внешним API).
